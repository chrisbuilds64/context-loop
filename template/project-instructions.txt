This project uses Context Loop. How it behaves is written in context/rules.md. Read that file at
the start of every session and follow it. context/README.md is the map: every file the loop uses,
what it holds, and what to edit to change the behaviour.

The procedures are plain files in loop/. Three things are different in this environment, because
the procedures were written for a terminal:

- Where they tell you to run a command such as /session-start, read the file of that name in
  loop/ instead and follow it.
- Where they tell you to commit, do that only if this folder is a git repository. If it is not,
  say so once and carry on.
- There is no session-start hook here. Where a procedure says the hook reports something, work it
  out from the files instead.

What I will say, and what it means:

  "start"        begin the session   (loop/session-start.md)
  "keep this"    hold on to what just happened, mid-session (loop/observe.md)
  "close"        end it              (loop/session-end.md)
  "todo"         show the work list  (loop/todo.md, loop/todo-add.md, loop/todo-done.md)
  "security"     the security audit  (loop/security-audit.md)
  "docs"         the documentation audit (loop/doc-audit.md)
  "new agent"    add a second agent with a different stance (loop/new-agent.md)
  "loop?"        list these and say which ones have run in this project before
